     Plan: Align Prototype Visual Styling with Tide Reference Design

     Context

     Marc wants the eInvoicing prototype to look and feel closer to the Tide app
      design shown in the reference screenshots (Create Invoice screen). The
     design tokens and component architecture are already correct — the fixes
     are targeted refinements to font rendering, shadow, banner sizing, icon
     rendering, and color saturation.

     ---
     What's Off vs. the Reference (Images #2 and #3)

     0. Font: Mulish needs tuning to read like GT Walsheim

     - Current: Mulish loads correctly (Next.js next/font/google, weights
     400–900, variable --font-mulish set on <body>), but GT Walsheim is a
     geometric sans-serif with tighter tracking and more even stroke weight —
     Mulish reads looser and rounder without adjustment
     - Reference: Headings are tight and punchy; body text is slightly condensed
      in feel
     - Fix A — Letter-spacing tweaks in globals.css: Add global rules to tighten
      heading rendering:
     h1, h2, h3 { letter-spacing: -0.02em; }
     - And in component inline styles, tighten title-weight text from
     letterSpacing: '-0.01em' to '-0.02em'
     - Fix B — Self-host GT Walsheim (when files become available): Replace the
     Mulish import in layout.jsx with localFont from next/font/local pointing to
      public/fonts/GTWalsheim-*.woff2. The CSS variable name (--font-mulish) can
      be renamed to --font-brand — update one place in globals.css
     - Fix C — Intermediate substitute: If GT Walsheim files aren't available
     yet, swap Mulish for Plus Jakarta Sans (Google Font, closer geometric match
      to GT Walsheim) — one line change in layout.jsx import

     1. Cards don't visually float on the gray canvas

     - Current: --ds-shadow-card: 0 2px 0 rgba(11, 27, 59, 0.02) — essentially
     invisible
     - Reference: Cards clearly lift off the #F0F2F8 background with a soft
     shadow
     - Fix: Change card shadow in globals.css to use --ds-shadow-1 (0 1px 2px 
     rgba(11,27,59,0.06)) and apply --ds-shadow-2 as the Card component default

     2. Banner text is too small (12px → 14px)

     - Current: All banners use --ds-fs-caption (12px) for body text
     - Reference: Banner text is clearly ~14px — comfortable reading size
     - Fix: Change banner font-size from var(--ds-fs-caption) to
     var(--ds-fs-meta) in the three banner blocks inside EinvoiceToggleSection
     and the bottom action bar in invoices/new/page.jsx

     3. The "ⓘ" info icon uses a <text> SVG element (cross-browser fragile)

     - Current: <text x="12" y="16.5" ... fontSize="13">i</text> inside SVG —
     renders inconsistently
     - Reference: Clean filled circle with white "i"
     - Fix: Replace with a path-based <path d="M11 
     17h2v-6h-2v6zm0-8h2V7h-2v2z"/> inside the filled circle SVG in the
     NOT_REGISTERED banner

     4. Bottom action bar banner includes an icon (doesn't match Image #3)

     - Current: Bottom action bar (cannotSend block) renders a clock/info SVG
     icon alongside the text
     - Reference (Image #3): Bottom amber/blue banner is text-only — no icon
     - Fix: Remove the <svg> from the bottom action bar banner (lines 414–418 of
      invoices/new/page.jsx), keep icon only in the mid-card banners where Image
      #2/3 show them

     5. Customer avatar background too washed out

     - Current: background: 'var(--ds-blue-softer)' = #EDF1FF (very pale)
     - Reference: Avatar bg is a noticeably more saturated lavender-blue
     - Fix: Change avatar background in CustomerAvatar to var(--ds-blue-soft)
     (#D6E0FF) — already a token in globals.css

     6. Banner border-radius slightly undersized

     - Current: borderRadius: 'var(--ds-radius-sm)' (10px) for banners
     - Reference: Banners appear to have ~12px corner radius
     - Fix: Change banner borderRadius from var(--ds-radius-sm) to
